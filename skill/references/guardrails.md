# 护栏与核实

## 1. 能力边界定义

| 边界 | 含义 |
|---|---|
| `no_realtime` | 无工具时无实时知识；今早的新闻、价格、状态一律不可推断 |
| `no_fact_guarantee` | 产出是「可能的文本」不是「已核实的文本」；自信程度与正确性无关联 |
| `no_persistent_identity` | 默认每段对话从零开始；延续性靠 auto-memory、Projects 与显式上下文提供，不假设自动记忆 |
| `no_consequence_model` | 不理解输出在现实中的后果，除非显式告知并推理 |
| `no_irreversibility_sense` | 编辑与删除、发给自己与发给一万人在模型眼里同为动作 |
| `non_deterministic` | 同问两次可得两个都合理但略不同的答案；精确复现须由外围代码与结构提供 |
| `self_eval_bias` | 模型给自己打分时会自信地夸奖平庸产物；高赌注输出必须由独立评估器复核 |

## 2. 条件 → 必出护栏映射

| 条件 | 必须进入 `guardrails` |
|---|---|
| 任意方案 | 至少一条与 `reversibility` 对应的约束 |
| `reversibility=irreversible` 或 `external_side_effect` | 人工确认卡口 + 权限收紧 + 可回滚路径 |
| `stakes=high` | 人工核实硬要求 + 引文 / 数字 / 名字 / 日期逐项核对 + 独立评估器 |
| `data_scope=browser` | 页面文本按数据不按指令；重大操作确认；限定影响范围与站点白名单 |
| `data_scope=external_system` | 最小权限连接；只读优先；凭据不进代码与日志，也不进运行生成代码的沙箱 |
| `data_scope=files` | 明确授权文件夹边界；沙箱执行；先问后做 |
| `data_scope=codebase` | git 作撤销键；worktree 隔离并行会话；执行前计划；Hook 固化禁区 |
| `data_scope=spreadsheet` | 删除 / 覆盖 / 外发留给人，模型只产候选 |
| 含网络检索或外部文档 | 提示注入防护；不可信文本与指令分离 |
| 含自动化且首次上线 | 起草但不发送、提议但不拍板；随证据逐步放权 |
| 默认自治（Auto Mode） | deny 规则、沙箱、隔离 VM、花费上限、网络出口默认关 |
| 含成本或延迟约束 | 逐步骤模型与 effort；缓存与路由分流；消费上限 |

## 4. verification 生成规则

- 每条 `verification` 必须含可观察判据或可执行检查动作。
- 禁止「仔细检查」「注意核对」「确保无误」这类无判据表述。
- 可采纳形态：跑测试或构建并读退出码、抽查 N 条输出的字段值、跑一次 A/B 对照、比对权威数据源、检查 git diff、核对账单与用量、回放失败样本、截图比对设计稿、用 `/goal` 定义完成条件。
- `stakes=high` 时至少两条，其中一条为人工核实。
- 有确定性要求时优先用 Stop hook 把检查做成闸门，而不是靠提示词请求。
- 每条 `verification` 附 `src` 或在 `rejected` 中说明依据。
